Four steps, in order, because each one feeds the next. Step one: run the Build Check with Resource 1. Score the five questions, do the math with what the scenario gives you, and reach a verdict. Write down what’s missing as questions for the director. About an hour. Step two: list every data flow the solution needs, and map each one to a pattern with the decision tree in Resource 4. Thirty minutes. Step three: write the Interface Design Document with Resource 5. All eight sections. This is the longest step. Step four: review the sample feed — next slide. One important rule. If your verdict comes out as “Don’t build yet,” you’re not done. Do steps two to four anyway, for the pilot you would run once the blocking issue is fixed — and say what has to change first. That’s exactly what you’d do at work.
