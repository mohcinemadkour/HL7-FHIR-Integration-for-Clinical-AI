Now it’s your turn. Step one: pick a real integration request. If you work in healthcare, use one from your own backlog — that’s where you’ll learn the most. If you don’t, use the readmission-risk scenario in the resources for this lecture. Step two: run the Build Check. Score all five questions — Go, Caution or Stop — with a one-line reason for each, and do the math for both sides. Step three: fill in the Build Decision Record template. You’ll find the template and my completed example for the sepsis pipeline in the resources. Do yours first, then compare. Budget about an hour. If you finish in ten minutes, you probably wrote “clinicians will find it useful” somewhere — go back to question one. Post your verdict in the Q&A if you want feedback. I’m especially interested in the ones that came out as “Don’t build.” In the next lecture, we’ll take the requests that passed and answer the next question: which pattern? HL7 v2, FHIR, a plain API, or a CDS Hook. See you there.
