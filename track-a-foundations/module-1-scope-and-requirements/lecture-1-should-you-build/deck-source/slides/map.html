Here’s how Module 1 is laid out. Three lectures, three decisions, in this order. Today, lecture 1: should you build this integration at all? You’ll leave with a Build Decision Record — a one-page document that captures the decision and the reasons behind it. Lecture 2: if the answer is yes, which pattern? A real-time HL7 v2 feed, a FHIR query, a bulk export, a plain API, or a CDS Hook inside the EHR workflow. Each one has a very different cost and failure profile. Lecture 3: you’ll write the Interface Design Document — the spec that the interface team, the clinical owner and you can all sign. Notice the order. Most teams start with lecture 3, or skip straight to Track B and start coding. We’re going to earn the right to build first.
