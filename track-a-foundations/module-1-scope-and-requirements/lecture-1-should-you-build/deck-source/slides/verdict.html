MAKING THE CALL

From five scores to one decision

Build

All Go — or Cautions with a written fix.

Pilot

Two or more Cautions. One unit, small scope, a fixed end date.

Don’t build — yet

Any Stop. Fix it, or take the lighter path.

Sepsis pipeline: Go, Caution, Go, Go, Go → Build, with missing-lactate handling as a requirement.

Now we turn five scores into one decision. The rule is simple on purpose. Build: every question is a Go — or you have a Caution, and you’ve written down exactly how you’ll handle it. Pilot: two or more Cautions. Too much uncertainty to commit fully, but enough promise to test. Keep a pilot honest: one unit, a small scope, and a fixed end date with the metrics from question five. A pilot without an end date is just a build without a budget. Don’t build — yet: any Stop. A Stop doesn’t mean the problem isn’t real. It means something has to change first: find the decision owner, fix the data timing, name a run owner, define the metric — or take a lighter path from the ladder. What about must-haves — a regulatory requirement, a safety mandate? Run the check anyway. You won’t decide whether to build, but the check tells you how to build it so it survives: who owns it, what pattern, how you’ll prove it works. For our sepsis pipeline: Go, Caution, Go, Go, Go. That’s a Build — with handling missing lactate values written in as a requirement. And one more thing: this is not a decision you make alone. Make it with the clinical owner and the interface lead, and have them sign the record.
