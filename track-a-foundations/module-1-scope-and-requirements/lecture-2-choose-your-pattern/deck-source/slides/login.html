“WE’RE BUILDING A FHIR INTEGRATION” — WHICH ONE?

Does a person log in?

NO · SYSTEM TO SYSTEM

SMART Backend Services

  1. Your service signs a JWT with its key
  2. Auth server returns an access token
  3. Service calls FHIR — no human involved

Pipelines, feature jobs, Bulk $export

YES · USER FACING

SMART App Launch

  1. User opens the app from the EHR
  2. OAuth 2.0 login and consent
  3. App gets a token and patient context

Clinician apps, patient apps

• The distinction that confuses most teams. • “We're building a FHIR integration” — which kind? • Ask: does a person log in? • No → SMART Backend Services. Your service signs a JWT and gets a token. No human. • Used by pipelines, feature jobs, Bulk export. You'll build it in Track C. • Yes → SMART App Launch. User opens the app, logs in with OAuth, app gets patient context. • Same FHIR API. Different security, registration and testing. • Decide early. Finding out mid-build costs weeks.
