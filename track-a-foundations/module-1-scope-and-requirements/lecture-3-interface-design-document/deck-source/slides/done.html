DEFINE DONE FIRST

“It works” is only the bottom layer

1 · It works

Messages delivered, data complete, latency, uptime

Each layer stands on the one below. Write a metric for all three in the IDD.

Before we scope anything, let’s define what done means. At go-live, the technical team usually celebrates: messages are flowing, tests passed, it works. That’s layer one, and it matters — delivery, completeness, latency, uptime. But it’s only the bottom layer. Layer two: do people actually use it? For our sepsis alert: are cards being seen, are nurses acting on them, and what’s the override rate? Layer three: does it change the outcome it was built for? For sepsis, that’s time to escalation — the metric you defined in the Build Check. Each layer depends on the one below it. No reliable data, no trust. No trust, no adoption. No adoption, no outcome. So the first thing that goes into your IDD is at least one metric for each layer. If you can only measure layer one, you can only prove that it works — not that it was worth building.
