SECTION 3 · FIELD MAPPING

One lab result: HL7 v2 → FHIR

HL7 v2 field FHIR Observation Rule
PID-3 subject Look up Patient by MRN
OBX-3 code Local code → LOINC via mapping table
OBX-5 valueQuantity.value Numeric; reject if empty
OBX-6 valueQuantity.code Map to UCUM unit
OBX-11 status P → preliminary, F → final, C → corrected
OBX-14 effectiveDateTime ISO 8601 with time zone
Section three is the mapping. Here’s what it looks like for one lab result going from an HL7 v2 ORU message to a FHIR Observation. PID-3, the patient identifier, becomes the subject — we look up the FHIR Patient by MRN, which is the matching rule we just decided. OBX-3, the test code, becomes Observation dot code — mapped from the local code to LOINC with the mapping table. OBX-5, the value, becomes valueQuantity dot value. It must be numeric, and if it’s empty, we reject the message. OBX-6, the units, map to a UCUM code. OBX-11, the result status: preliminary, final, corrected. Pay attention to this one. When a lab corrects a result, your features must update — otherwise your model scores the wrong value. And OBX-14, the observation time, becomes effectiveDateTime, in ISO 8601 with a time zone. Get the time zone wrong and your time-window features are off by hours. The interface team usually owns this table. Your job is to review it with model features in mind. You’ll build this exact mapping in Mirth in Track B.
