Let’s wrap up Module 1 — and with it, Track A. You made three decisions, and each one produced an artifact. Lecture 1: should we build? You ran the Build Check and wrote a Build Decision Record. Lecture 2: which pattern? You picked the right pattern for each data flow — HL7 v2, FHIR query, Bulk, SMART, CDS Hooks or documents. Lecture 3: what exactly are we building? You captured it all in the Interface Design Document: scope, codes, matching, errors, assumptions, metrics and owners. These three documents are what separate an integration that survives in a hospital from one that ends up abandoned. And notice: we haven’t written a line of code yet. That’s deliberate. From Track B on, every line of code you write will have a reason behind it.
